# 🏠 rental-contract-reviewer · 租房合同审查 Agent

> 把一份租房合同丢进去，30 秒帮你把里面的“坑”一条条揪出来——标明风险等级、法律依据和修改建议。
> 面向**真实生活痛点**：应届生 / 打工人租房子，合同看不懂、押金被坑、霸王条款吃哑巴亏。

这是一个**会真正调用工具的 Agent**，不是关键词匹配玩具：它先检索法律知识库找依据，再逐条判断并产出结构化报告。

---

## 为什么做这个项目

租房合同是**几乎人人都踩过坑、又普遍看不懂**的场景，非常适合拿来证明：

- Agent 能**检索 + 推理**（RAG 找法条 → 判断条款 → 给建议），而不是只会聊天；
- 工程上**有护栏、有评测**，知道“哪里会错、改了提升多少”。

## 它怎么工作

```
合同文本
   │
   ▼
┌─────────────────── 审查 Agent（手写 tool-calling loop）──────────────────┐
│  1. 识别疑似问题条款                                                │
│  2. search_law(query)  ──►  检索 knowledge/ 知识库（BM25）           │
│  3. list_redflag_types() ─►  对照红灯清单，避免漏查                  │
│  4. 汇总 → 输出结构化 JSON 报告（每条约据 + 建议）                   │
└────────────────────────────────────────────────────────────────────┘
```

两个工具：

| 工具 | 作用 |
| --- | --- |
| `search_law(query)` | 在 7 篇租房法律常识里做 BM25 检索，给每条风险找**真实法律依据**（RAG 落地） |
| `list_redflag_types()` | 列出关注的“红灯”风险类别，确保系统排查 |

**护栏（面试能讲的点）**：
1. 每条法律依据必须来自知识库检索，**禁止模型凭空编法条**；
2. 输出强制带“非法律意见”免责声明；
3. 步数护栏 `max_steps` 防止烧 token / 死循环；
4. 没填 API Key 时自动降级为**规则基线**（正则红线检测），流程照样跑、评测照样出。

## 评测成绩

在 3 份预设合同（坏 / 中 / 好）上跑：

| 合同 | 预期红线 | 规则基线命中 | 召回率 |
| --- | --- | --- | --- |
| 坏合同（8 处坑） | 8 | 8 | 100% |
| 中合同（2 处坑） | 2 | 2 | 100% |
| 好合同（无坑） | 0 | 0 | clean |

**规则基线整体召回率 100%（10/10）**。填了 Key 后 `eval/run_eval.py` 会再跑一遍真实模型作对比。

> 评测口径：用一组“预期红线特征串”去匹配审查报告，命中即算召回。规则基线完全确定，所以是稳定的硬指标。

## 目录结构

```
rental-contract-reviewer/
├─ knowledge/            7 篇租房法律常识（RAG 弹药库）
├─ src/
│  ├─ llm.py             通用 LLM 客户端（.env 感知 + mock 降级）
│  ├─ knowledge_base.py  BM25 检索
│  └─ agent.py           审查 Agent：工具循环 + 护栏 + 规则基线
├─ review.py             命令行入口
├─ web/                 零依赖网页前端（app.py + index.html）
├─ eval/                样例合同 + 评测脚本
```

## 技术栈

- **零第三方依赖**：只用 Python 标准库（`urllib` / `re` / `json`），clone 下来就能跑；
- 任何 OpenAI 兼容接口都能用（DeepSeek / 通义 / Kimi / OpenAI），改环境变量即可；
